## Setup

- Corpus: 138 documents (48 wikipedia, 90 arxiv) across 6 topics (compilers, computer_vision, cryptography, database_internals, distributed_systems, nlp), indexed as **179 chunks**.
- Embeddings: `voyage-4` (dense) + BM25 with server-side IDF (sparse), in Qdrant.
- Clusters: 12 (spherical k-means, k chosen by cosine silhouette).
- Cluster/topic purity: **84.4%** of chunks fall in a cluster whose majority topic is their own (topic labels are never shown to the clusterer).
- Queries: 180 (90 wikipedia, 90 arxiv), one per sampled passage, written by Claude from that passage and frozen in `data/eval/queries.jsonl`. The passage's document is the relevant document.
- Metrics use document-level relevance at cutoff k=10: a document counts at the rank of its first chunk.

### Configurations

- **Dense only**: Voyage embeddings, cosine kNN
- **BM25 only**: Sparse BM25, server-side IDF
- **Hybrid (RRF)**: Dense + BM25, reciprocal rank fusion
- **Hybrid + routing (m=1)**: Dense branch restricted to nearest cluster
- **Hybrid + routing (m=3)**: Dense branch restricted to 3 nearest clusters
- **Hybrid + MMR (λ=0.7)**: MMR over the fused candidate pool
- **Hybrid + routing + MMR (default)**: m=3, λ=0.7: the shipped configuration

## Caveats

- **One judged document per query.** Other documents that also answer a query count as misses, so absolute scores are a lower bound; comparisons between rows are the meaningful signal.
- **Generated queries.** Each is written from a single passage. Despite the paraphrasing instruction they can share vocabulary with it, which may favor lexical (BM25) matching relative to real user queries.
- **MMR is not a relevance optimization.** With one relevant document, diversity cannot raise nDCG. Its value shows up in the diversity table, and the Δ column shows what that diversity costs in ranking quality.
- Sample size: CIs come from 2,000 bootstrap resamples over queries (seed 0).
